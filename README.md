# SaparTravel

Проект для управления продуктовой разработкой и сопровождением веб-платформы/агрегатора услуг с короткими итерациями, прозрачной постановкой задач и контролем качества.

## Назначение

- Зафиксировать продуктовую стратегию и scope.
- Поддерживать рабочее пространство команды: GitHub Projects, документы, ADR, артефакты релизов.
- Обеспечить прозрачность процесса и быстрый запуск MVP.
- Контролировать качество, риск и эксплуатационную готовность.

## Структура репозитория

- docs/adr/ — архитектурные решения и выбор модели поставки.
- docs/requirements/ — стейкхолдеры, story map, требования и НФТ.
- docs/plan/ — WBS, релизы, зависимости, RACI, capacity.
- docs/security/ — RAID, модель угроз, соответствие и риски.
- docs/qa/ — тест-планы, UAT, postmortem.
- docs/ops/ — runbook, релизный план, откат и эксплуатация.
- docs/portfolio/ — итоговая сборка и портфолио проекта.
- notebooks/ — расчёты и оценки по рискам/стоимости.
- evals/ — набор для оценки ИИ-функции.
- scripts/ — автоматизация и скрипты DevOps/QA.
- src/ — исходный код приложения.
- tests/ — автоматизированные тесты.
- .github/workflows/ — CI/CD пайплайн.

## Рабочее пространство

- GitHub Projects: используется для backlog, sprint board и статусов задач.
- GitHub Wiki / docs: хранение концепций, решений и операционных инструкций.
- Репозиторий: источник истины по коду, документации, сценариям и артефактам релизов.

## Рекомендуемая модель поставки

В соответствии с ADR-001 выбран Scrum с двухнедельными спринтами, чтобы быстрее проверять гипотезы и выпускать инкременты.

## Быстрый старт

1. Ознакомиться с ADR-001.
2. Проверить дорожную карту в docs/plan.
3. Запустить локальную среду разработки и CI.
4. Согласовать backlog и приоритеты на очередной спринт.

## Основные роли

- Product Owner — приоритизация и критерии готовности.
- Scrum Master — ритм спринтов, блокады и улучшения.
- Team Lead / Tech Lead — архитектура, качество и интеграции.
- QA / Automation — проверки и регрессии.
- DevOps / Security — релизы, мониторинг и безопасность.

## Контакты и артефакты

Ключевые артефакты проекта находятся в директориях docs/* и должны обновляться вместе с изменениями продукта.
