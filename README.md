# SaparTravel

Учебное приложение для поиска, бронирования и **тестовой оплаты** туров.
React 19 / Router 7 / Vite 8, FastAPI / SQLAlchemy 2 / Alembic,
PostgreSQL 17, Docker Compose и Nginx. Интерфейс: **ru / kk / en**.
Каталог, предложения и отзывы демонстрационные; реальные деньги не списываются.

Турист выбирает выезд, участников и услуги, получает серверный расчёт в KZT,
резервирует места, оплачивает тестовой картой и видит подтверждение, историю,
уведомления и положенный возврат при отмене. Поставщик работает со своими
турами и клиентами. Администратор управляет каталогом, ролями, модерацией,
платежами, возвратами и обращениями.

Актуальные результаты запусков: [журнал проверок](docs/verification-results.md).
План и прогресс: [implementation-plan.md](docs/implementation-plan.md).
Эти локальные проверки не подтверждают готовность публичного коммерческого сервиса.

## Чистая демонстрационная среда

Нужны Docker Engine, Compose v2 и Python 3 для генератора конфигурации.
Из корня репозитория:

```bash
python3 scripts/setup_env.py --demo
docker compose up --build -d
docker compose ps
docker compose exec api python -m app.demo --credentials-file /tmp/sapar-demo-credentials.json
```

Генератор создаёт `.env` с уникальными секретами (0600). **Существующий `.env`
сохраняется**. Для ранее созданного файла явно установите в нём:

```dotenv
PAYMENT_DEMO_ENABLED=true
DEMO_PRIVATE_DATA=true
DEMO_MAILBOX_ENABLED=true
RESERVATION_MINUTES=15
PUBLIC_WEB_URL=http://localhost:5173
```

Затем пересоздайте сервисы командой `docker compose up --build -d`.
`DEMO_PRIVATE_DATA` и `DEMO_MAILBOX_ENABLED` разрешены только вне production.
Публичное окружение не создаёт известные пароли.

| Компонент | Адрес по умолчанию |
|---|---|
| Сайт | http://localhost:5173 |
| API / Swagger | http://localhost:8000/docs |
| Health API + БД | http://localhost:8000/api/v1/health |
| PostgreSQL | 127.0.0.1:5432 |

API применяет миграции, затем идемпотентный seed и запускает Uvicorn. Worker
после health API обслуживает истёкшие резервы и незавершённые операции.
Доступность мест проверяется также синхронно, без зависимости от worker.

## Тестовые доступы и наполнение

Первоначальный администратор: `ADMIN_EMAIL` / `ADMIN_PASSWORD` из приватного
`.env`. Команда `app.demo` отдельно создаёт четыре аккаунта со **случайными
индивидуальными** паролями:

| Email | Роль |
|---|---|
| demo-admin@example.com | admin |
| mountain-team@example.com | vendor |
| world-team@example.com | vendor |
| demo-traveler@example.com | traveler |

Посмотреть приватный файл:

```bash
docker compose exec api cat /tmp/sapar-demo-credentials.json
```

При первом создании сохраните его вне контейнера (права 0600):

```bash
docker compose cp api:/tmp/sapar-demo-credentials.json .env.demo-credentials.json
chmod 600 .env.demo-credentials.json
```

Файл исключён из Git. Пароли выдаются только для **новых** аккаунтов; повторный
запуск их не меняет. После пересоздания контейнера используйте сохранённую
копию или восстановление пароля. Не публикуйте эти данные в отчётах и CI.

Сохраняются минимум 24 направления и 24 тура. Явное private demo передаёт
только служебные туры двум активным поставщикам; служебная учётная запись
`catalog@sapartravel.invalid` остаётся заблокированной. Частные сценарии
создают завершённые и будущие поездки, настоящие записи симулятора, возврат,
связанные отзывы, уведомления и поддержку. Рейтинг считается по одобренным
отзывам. Пользовательские изменения и существующие даты не перезаписываются.

Промокод `SAPAR10` создаётся private demo: 10%, минимум 10 000 KZT, срок
год от первоначального наполнения, общий лимит 100, до трёх применений на
пользователя. Актуальные правила доступны администратору.

Для добавления будущего расписания **явной** командой:

```bash
docker compose exec api python -m app.seed --extend-departures
```

Она добавляет отсутствующие даты, не сдвигает существующие выезды и брони.

## Бронирование, платежи и возвраты

Все новые суммы — **KZT**, на всех языках: `249 900 ₸`. Сервер считает цену
выезда × участников + выбранные услуги − скидку; клиент не задаёт итог.
API передаёт деньги строками Decimal, БД хранит NUMERIC, вычисления без float.
Цена «от» и цена выбранного выезда различаются. В сделке фиксируются позиции,
имена участников, даты, переводы названия и версия учебных условий отмены.

```text
Бронь:   pending → confirmed → completed
            ↓          ↓
         expired    cancelled
            ↘ cancelled (до начала, если применимо)
Оплата:  created → requires_action / unknown → succeeded / failed / cancelled
Возврат: pending → succeeded / failed → повтор разрешённой попытки
```

- Pending занимает места до `expires_at`, по умолчанию 15 минут; повторная
  оплата и перезагрузка не продлевают срок. Истёкшие/отменённые резервы не
  блокируют продажи. Выезд и бронь блокируются в едином порядке PostgreSQL.
- Подтверждение происходит по успешному серверному результату оплаты.
  Обычное изменение статуса менеджером не обходит платёж.
- Нельзя бронировать начавшийся/отменённый выезд, оплачивать чужую, истёкшую
  или отменённую бронь. Завершение допустимо только после окончания поездки.
- `Idempotency-Key` обязателен для оплаты и административного возврата.
  Повтор с теми же параметрами возвращает ту же операцию; другие параметры
  отклоняются. Другой ключ не позволяет дважды успешно оплатить одну бронь.
- `unknown` требует сверки. Пока результат не установлен, повторное
  списание заблокировано. Поздний успех закрытого резерва компенсируется
  полным отдельным возвратом, сохраняя вместимость.
- Учебная отмена: за 7+ дней — 100%, за 2–6 дней — 80%, менее чем за 2 дня
  — 50%; отмена выезда поставщиком — 100%. Это демонстрационное условие,
  не утверждение о законодательстве. Договорный снимок виден до оформления.
- Успешные и ожидающие возвраты вместе не превышают оплату. Ошибка возврата
  не показывается как успех. Повторная отмена не возвращает деньги дважды.
- Промокод резервируется на действующий pending. Неоплаченная отмена и
  истечение освобождают лимит; оплаченная сделка засчитывается, в том числе
  при последующей отмене. Поздняя полностью компенсированная оплата, которая
  не подтвердила поездку, не расходует освобождённый промокод повторно.
  Отказ карты сохраняет срок резерва для повтора.
  Скидка, оставляющая менее 1 KZT, отклоняется; нулевая оплата не создаётся.

## Симулятор платежей

**Тестовая оплата. Деньги не списываются.** Вводить реальные карты нельзя.
Используйте автозаполнение инструмента в форме; имя — любое тестовое,
CVC `123`, месяц 01–12, год не ранее текущего. Текущий месяц окончания
действителен до его конца. Другие PAN, неправильная длина/контрольная сумма,
некорректные срок и CVC отклоняются сервером.

| Тестовая карта | Сценарий |
|---|---|
| 4242 4242 4242 4242 | Успех |
| 4000 0000 0000 9995 | Недостаточно средств |
| 4000 0000 0000 0002 | Отказ банка |
| 4000 0000 0000 3220 | 3-D Secure: успех, отказ, отмена, истечение |
| 4000 0000 0000 0119 | Временная недоступность |
| 4000 0000 0000 9235 | Тайм-аут; сверка установит успех |
| 4000 0000 0000 0341 | Тайм-аут; сверка установит отказ |

Симулятор хранит операции и историю в PostgreSQL и переживает рестарт.
Полный PAN/CVC не сохраняются в БД, браузерном хранилище и логах. История
содержит идентификатор инструмента и маску. Проверка идемпотентности хранит
необратимый HMAC параметров, без исходных реквизитов.

## Восстановление пароля и обращения

`/forgot-password` запрашивает одноразовую ссылку с ограниченным сроком.
Ответ не раскрывает существование аккаунта. В частном деморежиме доставку
можно прочитать администратором в кабинете или локально:

```bash
docker compose exec api python -m app.mailbox --recipient demo-traveler@example.com
```

Ящик не публичный. Повторное использование ссылки отклоняется, смена/сброс
пароля отзывает старые сессии. Logout отзывает конкретный JWT на backend;
роль и блокировка пользователя учитываются в каждом защищённом запросе.

Турист создаёт обращение, при необходимости связывает его со своей бронью.
Поставщик читает/отвечает только на обращения по своим турам; администратор
видит все. Ответ создаёт уведомление. Отзыв разрешён один раз на завершённую
собственную поездку, публикуется после модерации.

## Архитектура и модель данных

```text
React → Nginx / Vite → FastAPI /api/v1 → PostgreSQL
                         ↓                 ↑
                 identity / catalog / commerce / engagement
                         ↓                 ↑
                  PaymentProvider / MailDelivery / worker
```

Схема и обоснование 3НФ: [ER-модель](docs/er-model.md),
[словарь полей](docs/postgresql-schema.md), [ADR-003](docs/adr/ADR-003.md).
Переводы, галерея, программа, услуги, участники, позиции, попытки оплаты,
возвраты и сообщения — отдельные строки с FK/UNIQUE/CHECK. Договорные снимки
и условия — исторические документы; они не обновляются при изменении тура.

Аналитика `/manage/analytics` ограничена собственными турами vendor; admin
видит все. Фильтры `from/to` — даты Asia/Almaty. Заказы и операции фильтруются
по созданию, вместимость — по началу выезда. Оборот подтверждённых заказов,
полученные платежи, успешные возвраты и чистые поступления показаны отдельно.
Комиссионного реестра нет: доход платформы `null`, а не вымышленный процент.
Исторические валюты считаются раздельно. CSV нейтрализует формулы и экспортирует
до 10 000 строк; кавычки/переносы корректно обрабатывает csv.writer.

Основные маршруты UI: `/`, `/explore`, `/trips/:slug`, `/checkout/:slug`,
`/bookings`, `/bookings/:id`, `/favorites`, `/compare`,
`/saved-searches`, `/notifications`, `/support`, `/recommendations`, `/account`, `/manage`,
`/login`, `/register`, `/forgot-password`, `/reset-password`.
Полный контракт API доступен в Swagger; защищённые запросы используют bearer JWT.

## Обновление существующей базы и USD → KZT

Перед обновлением:

```bash
bash scripts/backup_db.sh
docker compose up --build -d
```

Не удаляйте volume. Новые миграции переносят существующий каталог и сохраняют
историю `0001`. Для старого USD-каталога цены туров/выездов умножаются на
**500 — явно заданный учебный коэффициент**, не рыночный курс. Исходное
значение/валюта и правило сохраняются в `currency_conversion_records`.

Старые брони остаются в исходной валюте и сумме; KZT-эквивалент сохраняется
отдельно. Старые confirmed/completed не объявляются оплаченными. Прежние
pending получают истёкший резерв; существующая история сохраняется. Старые
независимые деморейтинги обнулены до появления проверенных связанных отзывов.
Финансовые учебные материалы KZT не пересчитываются.

Нормализующие миграции не предлагают разрушительный downgrade. Откат требует
проверенной резервной копии и согласованной версии кода. Восстановление и
диагностика: [runbook](docs/ops/runbook.md).

## Локальная разработка

Требуются Python 3.12+, Node 22.12+, PostgreSQL 17. БД можно оставить в Docker.

```bash
python3 scripts/setup_env.py --demo
docker compose up -d db
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
```

В первом терминале:

```bash
set -a
source .env
set +a
cd backend
../.venv/bin/alembic upgrade head
../.venv/bin/python -m app.seed
../.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором: `npm --prefix frontend run dev`. В третьем с тем же окружением:
`cd backend && ../.venv/bin/python -m app.worker`.
`API_PROXY_TARGET` меняет backend Vite для dev/preview; по умолчанию 8000.

## Внешние сервисы и границы демонстрации

- `app/adapters/demo_payments.py`: `PaymentProvider` и сохраняемый симулятор.
  Настоящая интеграция требует подписанных событий, провайдерской сверки и
  outbox; сетевой вызов нельзя держать внутри долгой блокировки БД.
- `app/services/mail_service.py`: `MailDelivery`, локальная доставка в БД.
  SMTP/SMS и настоящая банковская система не подключены.
- Каталог и отзывы синтетические, изображения Unsplash имеют локальную
  безопасную заглушку. Реальные доступность/тарифы поставщиков не заявляются.
- JWT хранится как bearer в браузере; нужны HTTPS, защита от XSS, внешние
  backup/мониторинг и нагрузочная проверка перед публичным размещением.
  Rate limit в памяти процесса; несколько реплик требуют общего шлюза.
- Политика отмены учебная. Комиссии и юридически значимые банковские
  документы не моделируются. ICS и подтверждение брони — демонстрационные.

### ЛЗ 8: финансовая модель и комплект сдачи
