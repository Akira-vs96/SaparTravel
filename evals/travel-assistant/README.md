# ЛЗ 12: eval туристического консультанта

## Статус и ограничения

`dataset.jsonl` содержит 34 **синтетических** запроса для первичного прогона; 12 отмечены как сложные. Четыре последних кейса отдельно проверяют поиск без заданной страны, выбор страны по просьбе пользователя, смену бюджета и повторный поиск. `current_filters` в этих кейсах — синтетический снимок предыдущего ответа сервера. Это не реальные обезличенные обращения заказчика. Поле `expected` — предложение ИИ для dry run, а не человеческий эталон. Результаты не доказывают производственное качество, экономию времени или рост конверсии.

Формы [A](annotation-a.csv) и [B](annotation-b.csv) намеренно скрывают предложенные метки и оставлены пустыми. Два человека заполняют их независимо. После сравнения расхождения решает Product Owner; имена и время проставляют сами разметчики. ИИ не может подтвердить, что эта работа сделана людьми.

## Эксперименты

- `rules`: объяснимый regex/keyword parser без LLM.
- `zero-shot`: общая инструкция производственного консультанта без примеров.
- `few-shot`: та же инструкция плюс три фиксированных демонстрационных примера.
- Для обеих Gemini конфигураций: `temperature=0`, `seed=42`; сохраняются сырые JSON-ответы, версия модели, время и фактические Gemini token counts.
- Метрики: exact match всего набора фильтров, точность каждого поля, macro/micro F1 по типам слотов. Цены/наличие мест не оцениваются: их возвращает серверный каталог.

Для F1 каждый слот (budget, category, duration, travelers, destination, date_from, date_to) считается отдельным типом: exact value — TP, неверное или лишнее значение — FP, пропуск ожидаемого значения — FN. Macro F1 усредняет семь slot F1 и не считает верные пустые поля true positive. Поэтому основной критерий остаётся exact match всей записи и точность каждого поля.

Набор и baseline сделаны вместе, поэтому их диагностические оценки смещены. Не выбирать победителя по этим числам; для честного сравнения сначала заморозить набор и правила, затем оценить новый человечески размеченный holdout.

## Две слепые разметки

Каждый разметчик независимо заполняет форму [A](annotation-a.csv) или [B](annotation-b.csv). Не открывайте `expected` в `dataset.jsonl` до завершения разметки. Категории берите строго из enum каталога; неизвестное направление и неуказанные фильтры оставляйте пустыми. `travelers` по умолчанию равен `1`, если собеседник не назвал число.

После заполнения:

```bash
.venv/bin/python -m scripts.course.compare_travel_annotations
```

Скрипт проверяет две разные подписи, полноту и расхождения. При споре он только создаст отчёт `annotation-comparison.json`, но не выберет «правильную» сторону. PO фиксирует своё решение с причиной; после разрешения всех строк создаётся `human-gold.jsonl`. Человеческие метки реальных обезличенных запросов можно передать eval так:

```bash
.venv/bin/python -m scripts.course.travel_assistant_eval --human-gold docs/labs/lab-12/travel-assistant-evidence/human-gold.jsonl --overwrite
```

## Запуск

```bash
.venv/bin/python -m scripts.course.travel_assistant_eval
```

Скрипт читает `GEMINI_API_KEY` из окружения или локального игнорируемого `.env`, получает список категорий и направлений с сайта, отправляет 68 запросов (34 на конфигурацию) и пишет артефакты в `docs/labs/lab-12/travel-assistant-evidence/`. Не добавляйте ключ в аргументы команды или файлы результатов. Повторно существующую папку скрипт не перезаписывает без явного `--overwrite`.

При 10,000 и 100,000 запросов стоимость рассчитана для стандартного платного тарифа. Google также публикует бесплатный тариф; его квоты и условия хранения нужно проверить в аккаунте. На бесплатном тарифе запросы/ответы могут использоваться для улучшения продуктов. Используйте в упражнении только синтетические тексты.
