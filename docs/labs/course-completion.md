# Полный учебный комплект по 15 лабораторным

Дата сборки: 31.10.2026. Основание — исходная DOCX-методичка и её SHA-256 в
[реестре](manifest.json). Все **275 шагов и критериев лабораторных** сопоставлены
с артефактами; ещё два административных требования вынесены в
[лист настоящей сдачи](submission.md). Аудит проверяет не только существование
файлов, но и соответствие текста каждого требования оригинальному абзацу.

Для недостающих командных занятий подготовлены законченные **учебные
симуляции** с явно вымышленными участниками SIM. Они дополняют настоящий код,
источники и результаты запусков. Реальные интервью, подписи и внешняя приёмка
не отмечены проведёнными из-за появления этих файлов. Разрешение использовать
симуляцию ЛЗ9 получено от пользователя; принятие учебных альтернатив
преподавателем для остальных работ ещё не подтверждено.

## Что пересчитывается программно

[practice.py](../../scripts/course/practice.py) читает отдельный сценарий каждой
ЛЗ и заново считает деньги, capacity, Монте-Карло, DORA, экономику времени,
WSJF и длительность текста. Участие людей всегда остаётся `false`.
Параметр `--check` ничего не переписывает и завершается ошибкой при изменённом
сценарии, несовпавшем расчёте, отсутствующем доказательстве или неполном
сопоставлении требований. Проверка включена в CI.

```bash
.venv/bin/python -m scripts.course.practice
.venv/bin/python -m scripts.course.practice --check
.venv/bin/python -m scripts.course.audit --output docs/labs/evidence/audit.json
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -q
```

Генератор ЛЗ9 остаётся отдельным: он моделирует переходы очередей, а не
подставляет готовые итоговые числа. Сценарии остальных упражнений не меняют
реальные GitHub-переходы, журнал ЛЗ9, пользовательскую БД или личные аккаунты.

## Проверяемые ограничения результата

В эксперименте ИИ уступил правилам; внедрение отклонено. В ЛЗ9 среднее время
цикла выросло, хотя p85 сократился. В ЛЗ13 экономия не покрывает разработку
за семестр. Эти отрицательные результаты сохранены как выводы расчётов.

Требование полного запрета прямого push в main конфликтует с прямым указанием
пользователя разрешить admin push. Исключение сохранено и отражено в ЛЗ10;
оно не скрывается за статусом полного выполнения исходного требования.

Оригинальная проверка `audit --require-complete` по-прежнему требует настоящих
подтверждений. [Покрытие упражнений](evidence/practice-audit.json) и
[фактическая готовность](evidence/audit.json) отвечают на разные вопросы.
