## Цели для согласования на планировании

Спринт 1: «Сотрудник отменяет бронь с обязательной причиной, а турист видит
историю и точную сумму возврата». Подготовлены API, интерфейс и регрессии.
Спринт 2: «Пользователь видит понятную ошибку с повтором при повреждённом
ответе каталога и продолжает работу после восстановления сервиса».
Предложенные недельные окна: 02–09.11 и 09–16.11.2026. Фактические цели,
даты и состав команды утверждаются участниками; события ещё не проведены.

## Ровно одно предлагаемое действие ретроспективы

Каждый исполнитель переводит начатую задачу в In progress и завершённую в
Review в тот же день. Предлагаемый координатор по WBS — Айдар Елнара,
подтверждение назначения ожидается. Начало 02.11, проверка 16.11:
не менее 95% взятых задач имеют оба перехода, все завершения имеют timestamp,
и для обоих спринтов рассчитываются mean/p85 cycle time и средний WIP.
Исходное качество данных: у наблюдаемых завершений отсутствуют start events.
Результат эксперимента пока отсутствует.

На каждой реальной 30-минутной ретроспективе участники заполняют
«продолжать / прекратить / начать», записывают дату и принятый итог. Этот
план не заменяет их протокол. После двух окон повторяется команда flow_report из
[отчёта ЛЗ](README.md); сравнение публикуется с исходной выгрузкой.

## Рабочий комплект для проведения

Предложенные окна: [02.11.2026 00:00, 09.11.2026 00:00) UTC и
[09.11.2026 00:00, 16.11.2026 00:00) UTC. Объём и даты подтверждаются
на фактическом планировании. Подготовленные функции продукта не считаются
принятыми командой только по наличию кода.

| Спринт | Проверяемый пользовательский результат | Демонстрация и подтверждение |
|---|---|---|
| 1 | Сотрудник отменяет бронь с обязательной причиной; турист видит историю и сумму возврата | Положительный и отрицательный API/UI-сценарии, независимое ревью и протокол демонстрации |
| 2 | Пользователь получает понятную ошибку и повтор при повреждённом ответе каталога | Ответы JSON null/HTML воспроизводятся; повтор восстанавливает экран; независимое ревью и демонстрация |

Для записи переходов подготовлен [рабочий журнал](journal/README.md).
Зафиксирован существующий факт: [очередь Review превышает лимит](evidence/board-current-policy.json).
Новые старты журнал блокирует до разбора текущего ревью; реальные задачи
можно завершать или возвращать на доработку. Подменять независимое ревью
автоматическим проходом тестов нельзя.

После реальных окон и последнего checkpoint:

```bash
.venv/bin/python -m scripts.course.flow_journal --directory docs/labs/lab-09/journal export --output test-results/lab09-observed.json
.venv/bin/python -m scripts.course.flow_report --snapshot test-results/lab09-observed.json --start 2026-11-02T00:00:00Z --end 2026-11-16T00:00:00Z --output-directory test-results/lab09-two-sprints
```

Экспорт не продлевает наблюдение автоматически: до фактического окончания
окна такой расчёт будет отклонён. При других согласованных датах меняются
границы команды, а не дата системных часов.

Отчёт сохраняет отдельные таблицы сравнения, каждого завершённого цикла,
времени каждой задачи в статусах, среднего WIP по дням и CFD. Календарная
и рабочая шкалы приведены отдельно; в рабочей используются Пн–Пт UTC без
праздников. p85 согласован с формулой Calc и [проверен настоящим LibreOffice](evidence/calc-percentile-check.json).

К данным прилагаются цель каждого состоявшегося спринта и фактический
[протокол ретроспективы](retrospective.md). План и автоматический отчёт
самостоятельно не удостоверяют проведение этих событий.
