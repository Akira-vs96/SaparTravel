## Фиксация работы

Исполнитель меняет статус в GitHub в момент фактической смены стадии и
сразу записывает тот же переход локально. Время ставит программа в UTC;
параметра для назначения прошлой даты нет. Автор и ссылка на реальное
подтверждение обязательны. Owner при старте — фактический исполнитель.

Например, после действительно выполненной проверки и перевода issue #16
из Review в Done выполняется команда, где actor и reference заменены
данными проверяющего и ссылкой на его проверку:

```bash
.venv/bin/python -m scripts.course.flow_journal --directory docs/labs/lab-09/journal transition --issue 16 --to Done --actor '<проверяющий>' --reference '<ссылка-на-проверку>'
```

Новая работа стартует через `transition --issue N --to 'In progress'
--owner LOGIN --actor LOGIN --reference URL`. Проверяются существование
issue, предыдущее состояние и лимит двух In progress на владельца.
При Review ≥3 новый старт и вход в Review отклоняются. Завершение проверки
и возврат уже проверяемой задачи на доработку разрешены: это обработка
существующей очереди. Сейчас Review=7, поэтому сначала требуется разобрать
реальную очередь; [проверка снимка](../evidence/board-current-policy.json).

CLI сохраняет локальный журнал. Статус в GitHub меняет сам исполнитель;
скрипт не выдаёт локальную запись за изменение удалённой доски.

## Закрытие окна наблюдения

В конце дня и спринта координатор сверяет журнал с реальной доской и
сохраняет checkpoint с автором и ссылкой на выгрузку/протокол сверки:

```bash
.venv/bin/python -m scripts.course.flow_journal --directory docs/labs/lab-09/journal checkpoint --actor '<координатор>' --reference '<ссылка-на-сверку>'
.venv/bin/python -m scripts.course.flow_journal --directory docs/labs/lab-09/journal export --output test-results/lab09-observed.json
```

Экспорт ограничен последней фактической записью; запуск команды спустя
неделю сам по себе не продлевает наблюдение. Расчёт отклонит окно до первой
или после последней наблюдённой даты. Начальное Done не увеличивает
throughput, а уже начатая до базового снимка задача не получает вымышленного
начала цикла. Для будущих окон применяется команда flow_report из
[плана эксперимента](../sprint-experiment.md).

## Сохранность и границы

Записи последовательно связаны SHA-256 и защищены файловой блокировкой
от одновременной записи. Изменение базового снимка или существующей записи
останавливает экспорт. Повторная инициализация поверх данных запрещена.
Хеши обнаруживают изменение файлов; личность автора, независимое ревью
и состоявшееся собрание подтверждаются приложенными внешними фактами.

[Тесты](../../../../tests/course/test_flow_journal.py) проверяют целый цикл,
лимиты WIP, доработку из полной очереди Review, сохранение данных при отказе,
изменённый источник и границы наблюдения. Тестовые события остаются во
временных каталогах и не попадают в этот журнал.
