# PM-ассистент: запуск и проверка

Выбран недельный статус из задач, CI и deployment-записей. Оценка сроков, приёмка и финансовые
согласования отклонены: цена ошибки высока, а человеческих решений у модели нет.

```bash
.venv/bin/python -m scripts.course.github_facts --output test-results/github.json
.venv/bin/python -m scripts.course.weekly_status --snapshot test-results/github.json \
  --start 2026-10-12T00:00:00Z --end 2026-10-19T00:00:00Z \
  --output-directory test-results/status
```

Скрипт также читает `GEMINI_API_KEY` и необязательный `GEMINI_MODEL` из
игнорируемого `.env`. В GitHub Actions ключ модели задаётся секретом
`GEMINI_API_KEY`; необязательная переменная `GEMINI_MODEL` выбирает модель. Если
Project V2 закрыт для стандартного `GITHUB_TOKEN`, добавьте секрет
`GH_PROJECT_TOKEN` с правом чтения проекта. Без него workflow пропускает Project
V2 и сохраняет этот пробел в снимке. Все числа считает Python. Gemini API
получает только агрегаты, даты периода и null-поля; названия и тексты задач,
переписка, исходный код и персональные данные в промпт не передаются.

Результат: facts.json, ответ Gemini, verification.json и status.md. В расписании
используется исправленный промпт версии 6; исходные версии и промежуточные
прогоны сохранены в `evidence/api-2026-11-27/`. Workflow сохраняет artifact, не
отправляет писем или сообщений.
Проверку и решение об отправке выполняет ответственный PM / владелец недельного
статуса. Локальный черновик появляется в каталоге из `--output-directory`; по
расписанию он прикладывается к запуску GitHub Actions как artifact
`weekly-status-draft`. Пока PM не проверил и не утвердил текст, его нельзя
пересылать команде как подтверждённый статус.
Проверяющий сверяет каждое утверждение: ID/цитата, настоящий факт, смысловая
или стилистическая ошибка, правка, своё имя и время. Проверка чисел не
доказывает смысловую достоверность; черновик без человека не публикуется.

## Запрещённые данные

Запрещено передавать модели:

- API-ключи, токены, пароли, DSN и приватные ключи: они дают доступ к аккаунтам,
  инфраструктуре и данным.
- Персональные данные, контакты и содержимое клиентских обращений: они могут
  идентифицировать человека и не нужны для агрегированного статуса.
- Платёжные реквизиты и коммерческую тайну: они чувствительны и не относятся к
  счётчикам задач.
- Код заказчика и закрытые материалы проекта: они принадлежат заказчику и могут
  содержать уязвимости или коммерчески значимые решения.
- Приватную переписку и индивидуальные оценки сотрудников: это не источник
  метрик, а раскрытие может нарушить конфиденциальность и повлиять на людей.
- Свободный текст issues: он может содержать любые из перечисленных категорий и
  недоверенные инструкции. Сборщик сохраняет его в локальном снимке, но промпт
  получает только рассчитанные агрегаты.

## Экономия

Нужны 3 ручных замера одного процесса: дата, исполнитель, границы, время.
Затем генерация + сплошная проверка + правка того же объёма. Время генерации
Gemini API пишется автоматически; проверяющий отдельно записывает время
проверки и правки.
Экономия = медиана ручных замеров − генерация − проверка − правка.
Окупаемость = часы разработки / экономия на запуск, только при положительном
знаменателе. Сейчас человеческих замеров и проверки нет: результаты null.
Два фактических периода сохранены в evidence; это окна наблюдения, не протоколы
утверждённых спринтов. Gemini API может расходовать лимит или платную квоту
аккаунта; фактический счёт не снимался. Раскрытие ИИ включено в сам отчёт.
