# PM-ассистент: запуск и проверка

Выбран недельный статус из задач и CI. Оценка сроков, приёмка и финансовые
согласования отклонены: цена ошибки высока, а человеческих решений у модели нет.

```bash
.venv/bin/python -m scripts.course.github_facts --output test-results/github.json
.venv/bin/python -m scripts.course.local_model --directory /tmp/sapar-model --serve
# В другом терминале:
.venv/bin/python -m scripts.course.weekly_status --snapshot test-results/github.json \
  --start 2026-10-12T00:00:00Z --end 2026-10-19T00:00:00Z \
  --output-directory test-results/status
```

Сборщик использует gh только для чтения. В CI — штатный read-only GITHUB_TOKEN,
без копирования персонального OAuth-токена оператора. `--skip-project` пропускает
данные owner-level Project; отсутствие не подменяется. Локальный runtime и веса
закреплены checksum. Все числа считает Python, модель получает только агрегат.

Результат: facts.json, сырые model-v1/v2.json, verification.json и фактический
status.md. Workflow сохраняет файл, не отправляет писем или сообщений.
Проверяющий сверяет каждое утверждение: ID/цитата, настоящий факт, смысловая
или стилистическая ошибка, правка, своё имя и время. Проверка чисел не
доказывает смысловую достоверность; черновик без человека не публикуется.

## Запрещённые данные

Секреты/токены/DSN дают доступ к инфраструктуре; контакты/тексты заявок содержат
ПДн; платёжные реквизиты не нужны PM-отчёту; приватные переписки и персональная
оценка людей не являются агрегатом проекта. Эти данные модели не передаются.
Свободные описания задач не добавляются автоматически из-за ПДн и чужих инструкций.

## Экономия

Нужны 3 ручных замера одного процесса: дата, исполнитель, границы, время.
Затем генерация + сплошная проверка + правка того же объёма.
Экономия = медиана ручных замеров − генерация − проверка − правка.
Окупаемость = часы разработки / экономия на запуск, только при положительном
знаменателе. Сейчас человеческих замеров и проверки нет: результаты null.
Два фактических периода сохранены в evidence; это окна наблюдения, не протоколы
утверждённых спринтов. Оба промпта реально прогнаны; смысловые ошибки ждут
проверяющего. Раскрытие ИИ включено в сам отчёт.
