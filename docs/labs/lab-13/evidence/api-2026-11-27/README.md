# Gemini API: два недельных черновика

Сбор фактов выполнен из сохранённого снимка [GitHub от 30.10.2026](../../../evidence/github-2026-10-30.json). Окна наблюдения: 12–19 октября и 19–26 октября 2026 года; правая граница не включена. Это две недели фактической истории, а не подтверждение официальных границ спринтов.

Python сформировал агрегаты Issues, Project V2, Actions и Deployments. В Gemini Developer API через `generateContent` передавались только эти агрегаты и поля `null`; названия и тела задач, код и переписка в запрос не входили. Использована модель `gemini-3.5-flash-lite`. Ключ читается из `GEMINI_API_KEY` локально или из секрета GitHub Actions.

Для каждого окна рядом лежат `facts.json`, точный промпт и факты запроса, сырой ответ API и `verification.json`. Итоговые ответы версии 6 содержат 26 проверенных фактических утверждений суммарно. Числовая и структурная проверки обнаружили 0 ошибок; агентская сверка текста с фактами и снимком GitHub тоже обнаружила 0 ошибок. Это не подпись PM: поле человеческого проверяющего остаётся незаполненным.

## Что изменилось после проверки

| Версия промпта | Что обнаружено |
|---|---|
| 1 | 4 смысловые ошибки из 23 утверждений: значения Project V2 о задачах в работе и блокировках названы количеством проектов. Дополнительно модель вывела не переданную ей дату 25.10 из исключающей даты 26.10, двусмысленно записала конец первого периода и не указала, что ручной замер отсутствует, во втором отчёте. |
| 2 | Ошибки «задачи/проекты» исправлены. Остались двусмысленный охват нулевых deployments, неоговорённая исключающая правая граница и отсутствие ссылок на ключи в одном отчёте. |
| 3 | Модель повторно включила дату снимка в текст, хотя инструкция запрещала даты, и не приложила для неё исходный ключ. |

| 5 | Значения стали точнее, но в одном ответе остались грамматические ошибки и английский фрагмент. Проверка также сочла отсутствие записей о deployment ошибкой из-за отсутствия явного `0`; правило проверки уточнено, так как «записей нет» эквивалентно нулю записей. |
| 6 | Примеры терминов и строгий формат утверждений с ключами фактов устранили найденные смысловые, числовые, датировочные и стилистические ошибки в двух проверенных ответах. |

Смысловая доля ошибок в сравнении версии 1 и версии 6 снизилась с **4/23 = 17,4%** до **0/26 = 0%**. В знаменатель входят только явно сформулированные утверждения о метриках; сгенерированные даты и границы периода отражены отдельно в журнале. Выборка состоит из двух периодов и одной API-модели; результат не гарантирует качество будущих отчётов. Каждая новая публикация всё равно требует проверки человека.

## Время и стоимость

Суммарное время генерации двух итоговых черновиков версии 6 — 3,14 секунды по замерам API. Три ручных замера до автоматизации, длительность человеческой проверки и исправлений, а также фактические часы разработки не измерены. Поэтому чистая экономия и срок окупаемости остаются `null`. Бесплатность API и фактический счёт не проверялись; квота и тарификация зависят от аккаунта Google.

Вывод по эффекту: работающая интеграция не доказывает экономию сама по себе. На имеющихся данных нельзя утверждать, что ручной процесс стал быстрее или что автоматизация окупится за семестр. Для вывода нужны три ручных замера и время проверки/правки двух итоговых черновиков.

Раскрытие ИИ включено в оба отчёта. В них указано, что черновик составил Google Gemini API, факты подготовил Python, а проверяющий пока не назначен.
