## WSJF и портфельный WIP

[10 инициатив](../initiatives.csv) — внутренние альтернативы SaparTravel, не список проектов всех команд курса. Все три составляющие стоимости задержки и размер разделены, шкала 1/2/3/5/8/13. Расчёт повторно сортирует значения и допускает только первые три инициативы; остальные явно отложены. Одновременно запускать четвёртую нельзя без завершения одной из первых трёх.

Большой реальный платёжный провайдер не вытесняется оценкой «нравится/не нравится»: высокий размер снижает WSJF, предложение — выделить малый проверяемый срез, а не подкрутить числа. Утверждение портфеля настоящим спонсором не заявляется.

## Разговор о переносе — полностью разобранная ролевая игра

SIM-PM: «При текущем плане срок смещается на четыре недели; нужно выбрать один из трёх вариантов до 06.11».

1. Сдвинуть 20.12 →17.01, +28 дней. Упущенный эффект 21 700/365×28 =**1 664,66 USD**, исходный объём сохраняется.
2. Сохранить дату, перенести 24 ч из 171: новый план **147 ч**. Теряем второстепенную полировку/аналитику; обязательные контроли денег/мест остаются.
3. Добавить подтверждённый ресурс 24 ч ×10 USD/ч =**240 USD**. Дата сохраняется только если задачи допускают параллельность; риск координации остаётся.

SIM-спонсор: «А если поработать в выходные?» SIM-PM: «Эти часы не подтверждены в capacity; назвать их обещанием нельзя. Выберите перенос, сокращение или доступный ресурс». Решение модели — вариант 2; реальное решение спонсора не записывается автоматически. По умолчанию до ответа продолжается согласованный обязательный путь без объявления приёмки.

## Внедрение

[План по группам и неделям](../change-plan.md) сохраняет старый и новый способы параллельно T…T+2. Туристы проходят сценарий без подсказок, поставщики сверяют каталог, поддержка ведёт замечания, спонсор принимает решение по данным пилота. У каждого шага измеримый признак успеха; дата T назначается только настоящим принимающим.
