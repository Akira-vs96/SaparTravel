# ЛЗ 4: выполненное учебное упражнение

**Учебная симуляция.** Участники SIM и времена ролевых действий вымышлены; реальные источники и технические результаты отмечены отдельно. Этот разбор не удостоверяет внешнюю приёмку или личное участие.

[Основная ЛЗ](../README.md) · [Входные данные](scenario.json) · [Пересчитанный результат](results.json)

## Интервью с заказчиком — учебный диалог

Участники SIM-PO и SIM-A, условные 30 минут; все реплики придуманы для ролевого упражнения. SIM-PO: «Перед отменой хочу видеть сумму возврата и записанную причину». SIM-A: «Когда именно сумма должна стать известна?» SIM-PO: «До подтверждения; после действия она должна совпадать с обещанной».

Изменение **SIM-ST-10**: раньше «сотрудник отменяет бронь», после «до отмены показана сумма; пустая причина блокирует действие; история содержит причину и сумму». Негативные AC: пустая/пробельная причина, чужая бронь, повтор действия. Принимающий видит результат, а не устройство API.

## Интервью с туристом — учебный диалог

SIM-TOURIST: «Если каталог не загрузился, я хочу повторить поиск без повторного заполнения». SIM-A просит описать последний шаг и уточняет, должны ли остаться даты/бюджет. Ответ модели: «Да, иначе я начинаю заново».

Изменение **SIM-ST-03**: добавлены сохранение введённых условий, понятное сообщение и повтор запроса. Отрицательные AC: HTML вместо данных, JSON null, обрыв сети. Успешный HTTP-код сам по себе не означает успешный поиск.

## Изменения и связь с продуктом

| История модели | До | После | Приоритет |
|---|---|---|---|
| SIM-ST-10 | Отмена без явного результата | Сумма до действия, обязательная причина, история | Must |
| SIM-ST-03 | Только успешная выдача | Повтор, сохранение фильтров, три отрицательных ответа | Must |

Эти требования имеют настоящие технические проверки в [плане тестирования](../../../qa/test-plan.md) и [отчёте проверок](../../../verification-results.md). Они не доказывают, что интервью состоялись. [Исходные вопросы для настоящих интервью](../../../requirements/interviews.md), story map и НФТ остаются основными документами; модельный диалог не вносится в них как свидетельство заказчика.
