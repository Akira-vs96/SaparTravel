# ЛЗ 12. План ИИ-функции: evals, стоимость, риски

[Все лабораторные](../README.md) · [Архитектура](../../architecture.md)

## Результат и границы

Основная функция этой ЛЗ — ИИ-подбор тура из запроса обычным языком. Gemini извлекает параметры, сервер проверяет их по каталогу, а страница показывает пользователю распознанные фильтры и найденные карточки. Реальный endpoint ранее проверен синтетическим запросом (HTTP 200); в текущем изменении добавлен показ фильтров и подсказка, как исправить их следующим сообщением.

Для функции выполнены отдельный 34-примерный синтетический eval (12 сложных примеров), rule baseline, 34 zero-shot и 34 few-shot запроса к Gemini, метрики, разбор ошибок и расчёт стоимости. В набор добавлены многоходовые кейсы для исправления поведения, показанного в живом чате. Это диагностический dry run: примеры синтетические, ожидаемые фильтры подготовил ИИ, baseline разрабатывался вместе с набором. Поэтому качество на реальных запросах не установлено, а независимая разметка двумя людьми и отдельный holdout ещё нужны. По чек-листу готово 15 из 20 пунктов; пять остаются частичными или требуют человеческого участия.

Предыдущая проверка issue-routing на GitHub issues и учебное упражнение сохранены как дополнительные материалы. Они не оценивают туристический консультант.

## Выбранная функция проекта: ИИ-подбор путешествия

Туристический консультант реализован в приложении и использует Gemini API. Результаты ниже относятся только к диагностическому синтетическому набору, а не к реальным посетителям.

| Элемент | Предложение |
|---|---|
| Функция ИИ | Понимать запрос туриста обычным языком и преобразовывать его в фильтры каталога: бюджет на группу, число путешественников, категория, длительность, направление и даты. Если данных не хватает, консультант задаёт уточняющий вопрос. |
| Зачем | Упростить поиск для посетителей, которым неудобно выбирать параметры через форму. ИИ только разбирает запрос и объясняет подбор; актуальные туры, цены и свободные места возвращает сервер сайта. |
| Бизнес-метрика | Доля поисковых сессий, в которых посетитель открыл карточку тура, удовлетворяющего указанным ограничениям. Сравнивать с обычной формой подбора; дополнительно можно измерять время от начала поиска до открытия карточки. Текущие значения и эффект пока не измерены. |
| Метрика качества модели | Точное совпадение извлечённых фильтров с эталоном: отдельно по каждому полю и совместно по всему запросу. На синтетическом dry run exact match составил 1.000 у zero-shot и 0.971 у few-shot после серверной постобработки; значения предварительные, поскольку ожидаемые метки не проверены людьми. |
| Базовое решение без ИИ | Существующие формы каталога и рекомендаций: посетитель вручную задаёт параметры, а сервер детерминированно фильтрует туры по каталогу, бюджету, длительности, числу участников и наличию мест. Это исходный вариант для сравнения. |
| Проверка ограничений | Перед показом вариантов сервер применяет фильтры и данные каталога. Распознанные фильтры показываются пользователю и могут быть исправлены сообщением в чате. Модель не рассчитывает цены, не подтверждает наличие мест и не создаёт бронирование. Доля карточек, нарушающих жёсткие ограничения, должна быть нулевой; этот показатель ещё не измерен. |
| Критерий приёмки качества | На замороженном наборе с человеческим эталоном: не ниже 0,90 exact match всего набора фильтров; не ниже 0,95 точности по каждому полю; ноль неподдерживаемых направлений/категорий. Неоднозначная дата оставляется пустой с уточнением. Synthetic dry run не подтверждает критерий. |
| Правило отказа | Неизвестные значения и некорректные даты сбрасываются; при неоднозначных датах консультант просит уточнение. Числовая уверенность Gemini не калибрована, поэтому порог confidence пока отсутствует. |

Бизнес-метрика, которую предстоит сравнить с формой каталога: доля поисковых сессий, открывших карточку, соответствующую всем жёстким ограничениям. Время до подходящей карточки и пустая выдача — дополнительные метрики. Значения до/после пока не измерены.

### Диагностический прогон на синтетических запросах

34 тестовых запроса (12 сложных) прогнаны на `gemini-3.5-flash-lite`, `temperature=0`, `seed=42`; по 34 zero-shot и few-shot запросов. Фактическую версию и сырые ответы см. в [артефактах eval](<travel-assistant-evidence/>).

| Подход | Exact match фильтров | Macro F1 слотов | Ограничения |
|---|---:|---:|---|
| Regex/keyword baseline | 1.000 | 1.000 | Разрабатывался вместе с теми же синтетическими примерами; оценка смещена вверх |
| Gemini zero-shot + серверные правила | 1.000 | 1.000 | Правила удерживают фильтры между ходами, нормализуют явно написанный бюджет и включают поиск по явной просьбе; human gold отсутствует |
| Gemini few-shot + серверные правила | 0.971 | 0.995 | Осталась неоднозначность «на выходные»: 2 или 3 дня; human gold отсутствует |

Обе конфигурации формально проходят числовые пороги на синтетическом наборе: exact match не ниже 0.90, точность каждого поля не ниже 0.95. Это не подтверждает приёмку на реальных данных: набор синтетический, ожидаемые значения предложил ИИ, holdout отсутствует. Zero-shot с серверными правилами сравнялся с co-developed baseline, а few-shot уступил ему на одном кейсе; преимущество ИИ не доказано. [Разбор ошибок поштучно](<travel-assistant-evidence/error-analysis.md>).

Gemini usage metadata измерил в среднем 1,184 input + 106 output токенов на zero-shot запрос и 1,499 input + 88 output на few-shot. По стандартному платному тарифу, проверенному 20.11.2026, оценка составляет около **$6.19 / $6.69 за 10 000 запросов** или **$61.93 / $66.90 за 100 000** соответственно. При self-host допущении $64/мес точка равенства — примерно 103,000 zero-shot или 95,700 few-shot запросов/мес.; производительность своей машины на таком потоке не измерена. Бесплатная квота и фактический счёт зависят от тарифа аккаунта.
