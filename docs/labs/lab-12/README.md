## Результат и границы

Учебные недостающие действия разобраны в отдельном упражнении с исходными данными и расчётом; фактическая приёмка учитывается отдельно. Работает настоящая локальная Qwen2.5-0.5B через llama.cpp CPU, с pinned weights/runtime. 30 реальных названий issues, два промпта по 30 запусков, raw replies, token counts и F1 сохранены. По предложенным ассистентом меткам правила лучше модели; ADR отклоняет автоматическое применение. Две независимые человеческие разметки и решение спорных случаев отсутствуют; качество предварительное. Стоимость API — оценка по актуальному прайсу и измеренным Qwen tokens, не реальный счёт другого tokenizer.

## Гипотеза ИИ-функции для туристического сайта

Эта таблица описывает отдельную продуктовую функцию — ИИ-консультанта для поиска туров. Консультант реализован в приложении, но ещё не проверен с действующим ключом Gemini и не измерен на запросах туристов. Он не меняет функцию и результаты эксперимента выше: в рамках текущей ЛЗ 12 оценивалась классификация GitHub-задач.

| Элемент | Предложение |
|---|---|
| Функция ИИ | Понимать запрос туриста обычным языком и преобразовывать его в фильтры каталога: бюджет на группу, число путешественников, категория, длительность, направление и даты. Если данных не хватает, консультант задаёт уточняющий вопрос. |
| Зачем | Упростить поиск для посетителей, которым неудобно выбирать параметры через форму. ИИ только разбирает запрос и объясняет подбор; актуальные туры, цены и свободные места возвращает сервер сайта. |
| Бизнес-метрика | Доля поисковых сессий, в которых посетитель открыл карточку тура, удовлетворяющего указанным ограничениям. Сравнивать с обычной формой подбора; дополнительно можно измерять время от начала поиска до открытия карточки. Текущие значения и эффект пока не измерены. |
| Метрика качества модели | Точное совпадение извлечённых фильтров с эталонной разметкой запроса: отдельно по каждому полю и совместно по всем явно заданным ограничениям. Набор запросов нужно независимо разметить людям; результат текущей ЛЗ 12 для этой метрики неприменим. |
| Базовое решение без ИИ | Существующие формы каталога и рекомендаций: посетитель вручную задаёт параметры, а сервер детерминированно фильтрует туры по каталогу, бюджету, длительности, числу участников и наличию мест. Это исходный вариант для сравнения. |
| Проверка ограничений | Перед показом вариантов сервер применяет фильтры и данные каталога. Модель не рассчитывает цены, не подтверждает наличие мест и не создаёт бронирование. Доля показанных вариантов, нарушающих заданные жёсткие ограничения, должна быть нулевой; это проверка интеграции, а не достигнутый показатель качества модели. |
