# Нефункциональные требования (НФТ)

## 1. Производительность
- время отклика страницы: не более 2 секунд для обычных сценариев;
- API для основных запросов: не более 500 мс в средних условиях;
- скорость загрузки страницы для мобильных устройств: не выше 3 сек.

## 2. Доступность
- SLA на основной сервис: 99,5% и выше;
- ведение мониторинга и алертов для критических компонентов;
- восстановление после инцидента в рамках регламента.

## 3. Безопасность
- хранение токенов и чувствительных данных в защищённом виде;
- доступ на уровне ролей и прав;
- аудит действий администраторов и модераторов;
- соответствие минимальным требованиям по защите пользовательских данных.

## 4. Масштабируемость
- система должна обеспечивать рост числа записей, пользователей и транзакций без значительных архитектурных переделок;
- подходящий запас по CPU/RAM и вычислительным ресурсам.

## 5. Удобство сопровождения
- документирование архитектуры и процессов;
- CI/CD и автоматизация проверок;
- понятные соглашения по ветвлению, именованию задач и релизам.

## 6. Надёжность
- базовая резервная копия данных;
- восстановление после отказа;
- контроль ошибок в ключевых интеграциях.

## 7. Юридические и регуляторные ограничения
- соблюдение требований по обработке персональных данных;
- прозрачная политика конфиденциальности и пользовательских соглашений.

## 8. Качество данных
- корректность и согласованность информации о партнёрах, услугах и статусах;
- валидные проверки вводимых данных и бизнес-правил.
