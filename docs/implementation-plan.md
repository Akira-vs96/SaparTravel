# План реализации SaparTravel

Дата начала: 2026-10-23. Основание: `promt1.md`. Работа ведётся в существующем
репозитории; исходные миграции, учебные документы и рабочая БД сохраняются.

## Фактический аудит

- FastAPI + SQLAlchemy 2, React 19 + Router 7 + Vite 8, PostgreSQL 17 и Compose
  подтверждены исходниками. Имеются 24 направления/тура, три языка, роли,
  избранное, CRUD кабинетов, снимки брони и блокировка строки выезда.
- Нет платежей, возвратов, ограниченного резерва, участников, промокодов,
  отзывов, поддержки, уведомлений и восстановления пароля.
- Деньги каталога и бронирований — USD, выдаются как float. JSON используется
  для программы и услуг; требуется реляционное ядро и перенос данных.
- Демокаталог принадлежит заблокированной служебной учётной записи. Она
  останется заблокированной; отдельная явная команда подготовит активных
  демонстрационных поставщиков со случайными индивидуальными паролями.
- В Git до работы только неотслеживаемый пользовательский `promt1.md`.
- Исходные проверки запускаются на отдельном PostgreSQL 17, порт 55439,
  контейнер `sapartravel-implementation-test`; рабочий PostgreSQL не очищается.

## Решения и координация

- Модульный монолит; отдельные прикладные сервисы commerce и identity/
  engagement. Дополнительные инфраструктурные сервисы не требуются.
- Согласованные цены API — строки Decimal с двумя знаками, новые сделки KZT.
- Старый подтверждённый статус не доказывает оплату. Финансовые операции
  возникают только из фактов провайдера; исторические валюты не складываются.
- Симулятор и частные демосценарии включаются настройкой; реальные карты
  не принимаются. Полный PAN/CVC не сохраняется и не попадает в диагностику.
- Независимые frontend, commerce и engagement задачи делегированы согласно
  прямому указанию `promt1.md`; общие API согласуются до интеграции.
- Проверки выполняются в отдельных базах; рабочая среда не сбрасывается.

## Итог и эксплуатационные границы

Учебное приложение реализовано и запущено на http://localhost:5173.
Рабочая БД обновлена миграциями; исходные пользователи и 24 направления/тура
сохранены. Приватное наполнение создаёт активных поставщиков, связанные истории
и случайные доступы. Учебные финансовые документы не изменялись.

Реальный банк, подписанные webhooks, SMTP/SMS, публичный HTTPS, разделяемый
rate limit и нагрузочная приёмка относятся к следующей внешней интеграции.
Текущая реализация явно обозначает демонстрационный режим и не заявляет
готовность к публичной коммерческой эксплуатации.
