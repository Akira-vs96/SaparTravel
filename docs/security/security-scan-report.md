## Как работают сканеры

### Trivy

Trivy читает манифесты зависимостей и lock-файлы, определяет точные версии
пакетов и сравнивает их с базой известных CVE. Он не доказывает эксплуатацию
уязвимости атакой, а проверяет попадание установленной версии в известный
уязвимый диапазон и показывает версию, в которой проблема исправлена.

В проекте Trivy проверил `backend/requirements.txt` и
`frontend/package-lock.json`. Для frontend учитывались и транзитивные
зависимости — пакеты, которые пришли через другие npm-пакеты. Поэтому найденный
`source-map-js` отсутствует в `package.json`, но присутствует в lock-файле.

### Gitleaks

Gitleaks проходит по текущим файлам и истории Git и применяет правила для
известных форматов секретов и эвристики: имя переменной (`jwt_secret`),
контекст, длина и случайность строки, а также шаблоны API-ключей и токенов.
Поэтому он может находить не только production-пароли, но и похожие на секреты
тестовые значения. Код `--redact` скрывает содержимое найденной строки в выводе.

Проверка истории важна: удаление секрета из текущего файла не удаляет его из
старого коммита. Если найденное значение действительно использовалось вне
тестов, его нужно отозвать/заменить, а затем отдельно решить вопрос очистки
истории Git.

## Trivy: зависимости backend

Основная проблема — зафиксированный [PyJWT 2.10.1](../../backend/requirements.txt).
Trivy указал исправленные версии начиная с `2.12.0–2.15.0` в зависимости от
CVE. Самая серьёзная находка:

| Уровень | CVE | Пакет | Установлено | Исправление |
|---|---|---|---|---|
| Critical | CVE-2026-102268 | PyJWT | 2.10.1 | 2.14.0 |
| High | CVE-2026-102267, CVE-2026-102271 | PyJWT | 2.10.1 | 2.14.0 |
| High | CVE-2026-32597, CVE-2026-48526 | PyJWT | 2.10.1 | 2.12.0/2.13.0 |

Кроме перечисленных, найдены дополнительные Medium/Low CVE для PyJWT.
До обновления нужно проверить совместимость API токенов и прогнать backend-тесты.

## Gitleaks

Найдено 6 совпадений по правилу `generic-api-key` в тестовых значениях
`jwt_secret="REDACTED"`:

- `backend/tests/test_configuration.py:25`;
- `backend/tests/conftest.py:18`;
- те же строки в истории коммитов
  `04ba943`, `0634856`, `f2c0db3`, `01aecdbe`.

Это не production-секрет из `.env`, но он уже присутствует в истории Git и
потому не должен считаться полностью безопасным. Если эти значения когда-либо
использовались вне тестов, JWT-секрет нужно немедленно отозвать и заменить.
Удаление строки из текущего файла не удаляет её из истории.

## План исправлений

1. Обновить PyJWT до версии, закрывающей Critical и High CVE; запустить
   backend-тесты и проверить создание/валидацию JWT.
2. Обновить `source-map-js` через npm lockfile; выполнить frontend build.
3. Заменить тестовые JWT-значения на явно фиктивные низкоэнтропийные значения
   или добавить точное документированное исключение Gitleaks только для тестов.
4. Повторить оба сканирования и сохранить новый отчёт с датой.
5. До повторного чистого сканирования считать задачи B-01 и R-03/R-16
   незакрытыми: см. [security backlog](./security-backlog.md) и
   [RAID-лог](./raid.md).
