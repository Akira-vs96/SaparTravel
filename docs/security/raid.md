## 1. Правила

Риск — ещё не случившееся событие с вероятностью и влиянием. Проблема — уже
случившееся событие, поэтому для неё указываются срок устранения и статус.
EMV рассчитывается как `вероятность × влияние`, где влияние измеряется в часах
работы команды. Сумма EMV — обоснованный размер риск-резерва.

Оценки вероятности: 0,1 — низкая, 0,3 — средняя, 0,5 — высокая. Влияние
включает анализ, исправление, повторную проверку и возможную задержку.

## 3. Топ-5 и план реагирования

1. **R-03, секреты (6,0 ч):** запретить `.env` в Git, запускать Gitleaks до
   merge, при находке немедленно сменить пароль/секрет и проверить историю.
2. **R-16, зависимости (6,0 ч):** запускать Trivy для файловой системы и
   образов; HIGH/CRITICAL превращать в задачу с SLA 2 рабочих дня.
3. **R-01, PostgreSQL (4,8 ч):** проверять healthcheck, выполнять backup и
   еженедельный restore-test; при сбое включать режим инцидента.
4. **R-13, аудит (4,8 ч):** добавить единый request/event ID и проверять наличие
   записи для каждой административной операции.
5. **R-20, производительность (4,8 ч):** повторить smoke с 20 RPS, добавить
   индексы только по подтверждённым профилям и пересмотреть NFR.
