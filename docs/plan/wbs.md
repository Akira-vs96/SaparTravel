# WBS и план релизов

## 1. WBS проекта

### 1.1 Подготовка и стратегия
- Уточнение цели продукта
- Анализ рынка и конкурентов
- Формирование user stories
- Определение MVP

### 1.2 Дизайн и UX
- UX-процесс и user flow
- Прототипирование ключевых сценариев
- Дизайн-система
- Проверка usability

### 1.3 Разработка
- Архитектура и техническая постановка
- Backend
- Frontend
- Интеграции и API
- База данных

### 1.4 Интеграции и данные
- Синхронизация контента
- Сервисные интеграции
- Роли и доступы
- Логирование и аналитика

### 1.5 QA и безопасность
- Тест-план
- Автотесты
- Утверждение сценариев
- Проверка данных и безопасности

### 1.6 Релизы и эксплуатация
- CI/CD
- Deploy
- Monitoring
- Runbook
- Откат и поддержка

## 2. Релизы

### Release 1 — MVP
- каталог услуг;
- поиск и фильтрация;
- базовый профиль пользователя;
- карточка сервиса и партнёра.

### Release 2 — Transactions
- бронирование и оформление заявки;
- статусы и уведомления;
- базовая аналитика выбора услуги.

### Release 3 — Scale
- расширенные интеграции и оплаты;
- административный кабинет;
- рейтинг, отзывы, аналитика и оптимизация.

## 3. Зависимости

- UX и требования → архитектура → разработка.
- Разработка → интеграции → QA.
- QA → релиз → мониторинг.
- Операционная поддержка зависит от договорённости по SLA и runbook.

## 4. RACI

| Действие | Product Owner | Team Lead | Dev | QA | DevOps |
|---|---|---|---|---|---|
| Приоритизация backlog | A | C | C | I | I |
| Архитектура | C | A | R | I | I |
| Разработка функций | I | C | A/R | I | I |
| QA и UAT | I | C | C | A/R | I |
| CI/CD и деплой | I | C | I | I | A/R |
| Мониторинг | I | C | I | I | A/R |

## 5. Capacity

- 5–7 участников команды на ранних этапах;
- ритм: двухнедельные спринты;
- 70–80% времени на развитие продукта;
- 10–20% на устранение дефектов и поддержку;
- 10% на улучшения процессов и коммуникацию.
