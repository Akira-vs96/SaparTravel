# ADR-006: bounded Gemini pilot for natural-language tour search

**Date:** 2026-11-20
**Status:** engineering recommendation; Product Owner sign-off not recorded.

## Context

SaparTravel has a Gemini consultant that extracts budget, category, trip length, traveler count, destination and dates from chat, then asks the server to filter the existing catalog. A live smoke request returned HTTP 200 after the Russian category-label fix. That proves the integration responds; it does not establish quality or business impact.

The one function evaluated for this product decision is natural-language filter extraction. The deployed catalog form remains the no-model alternative. A separate experiment on GitHub issue routing is kept as course evidence but does not measure this travel feature.

## Recommendation

Keep the assistant available as a bounded search pilot beside the normal catalog form. Show the interpreted filters so the visitor can correct them in chat. Only the server reads prices, dates and availability from the catalog. The model cannot create bookings, take payments, send messages or change inventory.

This is not evidence that AI is better than the form. Keep the rollout only while a human can review every result and the ordinary catalog remains available.

## Acceptance and measurement

Before claiming the model is better, use at least 30 anonymized real traveler requests, independently labelled by two people, then have the Product Owner resolve disagreements. Include at least six ambiguous, short or mixed-language requests, freeze the set, and keep a separate holdout set.

Proposed model acceptance: at least 0.90 exact match for the complete filter record, at least 0.95 exact accuracy for each field, zero unsupported category/destination values, and invalid/ambiguous dates left blank with a clarification. Compare against the same requests parsed by the deterministic baseline and the ordinary form. Do not accept on macro average alone if any field misses its threshold.

Business outcome to measure against the form: share of search sessions that open a tour card satisfying the stated hard constraints; also measure median time to the first suitable card and empty-result rate. Current values, conversion lift and time saved are not measured.

## Alternatives considered

1. **Catalog form only.** Deterministic filters and current source of truth; user must enter structured fields.
2. **Keyword/rule parser.** Cheap, inspectable, can leave unknown values empty. The current synthetic baseline is not an unbiased estimate because it was built alongside the examples.
3. **Local model.** Keeps chat text on the server but needs its own quality, capacity and maintenance evidence; the existing tiny Qwen PM-classification run is not evidence about travel-filter extraction.
4. **Automatic booking or price answers.** Rejected. The model has no booking/payment authority and must not invent catalog facts.

## Risks and controls

See [travel assistant risk card](../labs/lab-12/travel-risk-card.md). The page identifies Gemini and displays the interpreted filters. The visitor can correct them in chat and chooses a catalog card; the application remains responsible for price and availability. On API failure the user can return to the catalog.

The assistant sends chat text, the validated filter state from the previous turn, and catalog option labels to Gemini. Do not include personal, contact or payment details. The account's free/paid data-use tier has not been verified; Google's [published pricing page](https://ai.google.dev/gemini-api/docs/pricing) says free-tier prompts/responses may be used to improve products, while paid-tier prompts/responses are not. The evaluation uses only synthetic prompts.

## Cost

Use the measured Gemini input/output token counts and the [published Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing) checked 2026-11-20. Gemini 3.5 Flash-Lite standard paid-tier rates are USD 0.30 per million input tokens and USD 2.50 per million output tokens (thinking tokens included). Include 10,000 and 100,000 requests/month. This is a paid-tier estimate, not the user's invoice; a free tier may have no token charge within quota.

Compare with the existing USD 64/month self-host planning assumption (USD 24 infrastructure + USD 40 administration). The break-even calculation is only arithmetic until throughput and machine availability at that scale are measured.

## Review trigger

Revisit after the human-labelled real-query set and holdout exist, the Product Owner accepts the labels, and a controlled comparison with the catalog form reports quality and business metrics. Roll back the assistant if it produces unsupported filters or the API failure rate blocks ordinary search.
