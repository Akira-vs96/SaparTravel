# ADR-004: измерения сервиса и исторические доказательства

Дата: 2026-10-30. Статус: принято для технической реализации; договорное
согласование параметров эксплуатации остаётся отдельным решением.

## Решение

SLI измеряются внешними HTTP-клиентами и журналами прикладных фактов.
Health API остаётся диагностикой, а контроль доступности проходит web,
каталог, вход, создание и отмену брони. Для эксплуатации явно создаются
технические туристы и скрытый контрольный тур; сервер помечает контрольные
сделки и исключает их из бизнес-аналитики. Safety manifest связывает узел
с контуром и fixture до первой записи.

PostgreSQL остаётся источником прикладного состояния. Копия и fingerprint
таблиц используют один экспортированный MVCC snapshot. Restore создаёт новую
БД и сверяет содержимое. Измерение длительности pg_restore не называется
восстановлением API: SLI-R отдельно требует отказ и пять успешных минут.

Поддержка хранит приоритет, календарный снимок, срок и первую человеческую
реакцию с автором. Срок считается в рабочих минутах Алматы. Исторические
неизвестные данные остаются неизвестными. Согласованный календарь не
подменяется автоматически выбранным перечнем праздников.

SLO считает все минуты; SLA исключает только явно подтверждённые интервалы
из одинаковых числителя и знаменателя. Сервисный кредит вычисляется Decimal
только при подходящих наблюдениях и согласованной плате. Инструменты не
создают договор, не списывают деньги и не оформляют приёмку от имени заказчика.

## Последствия

Добавлена обратимо развёртываемая прикладная версия с миграцией `0005`;
откат данных выполняется проверенным backup с соответствующей версией кода.
Системные timers не добавляют инфраструктурных зависимостей в транзакции API.
Они развёртываются на назначенных мониторинговых/backup-узлах с отдельными
приватными окружениями. Локальный тест подтверждает свой стенд, а независимость
внешних точек и эксплуатационное расписание подтверждает владелец этих узлов.
