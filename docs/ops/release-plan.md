# Выпуск, развёртывания и откат

Предлагаемое окно — вторник/среда 10:00–12:00 Asia/Almaty после подтверждения
стенда и принимающего. Это план, не обещание наличия production. Не выпускать
изменение в пик нагрузки или перед выходными. Координатор Delivery — Бердебек
Әмір по WBS; внешний владелец среды и замещающий пока не назначены.

## Термины DORA

Развёртывание — успешное применение конкретного commit на **именованный стенд**,
с записью GitHub Deployment, environment, SHA, временем и успешным smoke.
Зелёный CI, сборка образа или push не являются развёртыванием. Lead time —
от commit до успешного стенда. Неудачное изменение — deployment, которому
в течение суток потребовался rollback/hotfix из-за вызванного им дефекта;
инцидент связывается с deployment ID. Время восстановления — от наблюдаемого
отказа до подтверждённого восстановления. Нет реестра — показатель неизвестен.

## Перед выпуском

1. Delivery подтверждает scope, дату, принимающего и канал уведомления.
2. PR связан с issue; обязательные CI проверки зелёные, есть review другого участника.
3. Снимок данных проверен восстановлением в новую БД; исходная версия и SHA сохранены.
4. Миграция проверена на пустой БД и копии; совместимость отката описана.
5. Значения окружения проверены без печати секретов. Секреты переданы отдельно.
6. Указать среду, SHA, оператора и начать GitHub Deployment только при реальном применении.
7. По [runbook](runbook.md) применить версию и миграции, проверить health,
   основной сценарий, роли и отсутствие новых ошибок JS.
8. Только после smoke отметить deployment success; при ошибке — failure
   и запись инцидента. Сохранить фактические времена, без восстановления по памяти.

## Откат

1. **Назначенный дежурный владелец выпуска принимает решение единолично**
   при потере основного сценария, данных или разграничения доступа; начать
   в пределах 5 минут обнаружения. До назначения владельца выпуск блокируется.
2. Зафиксировать время, deployment ID, симптом и остановить дальнейший rollout.
3. Вернуть предыдущий совместимый образ/SHA по runbook. Не выполнять
   автоматический downgrade несовместимых миграций.
4. При повреждении данных восстановить проверенную копию в **новую** БД,
   сверить содержимое и переключить приложение согласованным действием.
5. Подтвердить восстановление пользовательским сценарием; для SLI-R —
   пять реальных успешных минут. Записать RTO/RPO и последствия.
6. Сообщить результат согласованным каналом, связать исправление с инцидентом.

## Улучшения процесса

| Изменение | Проверяемое ожидаемое улучшение | Пересчёт |
|---|---|---|
| Реестр deployments и связанный журнал инцидентов | Полнота записи ≥100% фактических выпусков; DORA получает измеримые знаменатели | После следующего реального выпуска, затем 06.11.2026 |
| Smoke не принимает HTTP 200 с null/HTML | Повтор дефекта некорректного ответа обнаруживается до приёмки; 2/2 отрицательных сценария проходят | В каждом PR |

Часы исправлений и общая фактическая capacity пока не измерены. Доля времени
на надёжность не объявляется историческим фактом; для следующего планирования
предлагается обсудить 20% и пересмотреть по журналу трудозатрат.
