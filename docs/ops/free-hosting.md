# Бесплатная публикация SaparTravel

Подготовлена схема **GitHub → Render Free + Neon Free**. Один контейнер
обслуживает React, FastAPI и worker; PostgreSQL хранится отдельно в Neon.
Платные сервисы, диски, отдельные worker и cron не используются.
До подключения аккаунтов, первого выпуска и успешной проверки публичного URL
эта конфигурация означает готовность к публикации, а не работающий внешний сайт.

## Подключение

1. В Neon выбрать организацию **Free**, создать новый проект `sapartravel`
   в AWS Frankfurt, PostgreSQL 17. Использовать прямое подключение `postgresql://…`
   с `sslmode=require`: session advisory lock worker требует одной настоящей
   PostgreSQL-сессии; transaction pooler здесь не подходит. Это новая БД, локальные
   аккаунты, платежи и персональные данные в неё не копируются.
2. В Render выбрать бесплатное рабочее пространство и New → Blueprint,
   подключить репозиторий `Akira-vs96/SaparTravel`, ветку `main`.
   [render.yaml](../../render.yaml) создаёт только один сервис с `plan: free`.
   Ввести `DATABASE_URL` из Neon и новые `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
   `JWT_SECRET` генерируется Render. Секреты вводятся в настройках сервиса,
   не в файлы репозитория, отчёты или чат.
3. Первый выпуск Blueprint запускает [Dockerfile.public](../../Dockerfile.public).
   При старте применяются миграции и добавляется публичный каталог; существующие
   записи не перезаписываются. `PUBLIC_WEB_URL` берётся из `RENDER_EXTERNAL_URL`.
   Приложение слушает порт Render `PORT`, по умолчанию 10000.
4. После появления адреса `https://<имя-сервиса>.onrender.com` проверить
   `/api/v1/health`, `/api/v1/experiences`, `/api/v1/release`, главную страницу
   и прямую ссылку `/forgot-password`. Сначала требуется успешный CI того же SHA.
5. В GitHub → Settings → Secrets and variables → Actions добавить secret
   `RENDER_DEPLOY_HOOK_URL` из Render → Settings → Deploy Hook; variables
   `PUBLIC_SITE_URL` (HTTPS-адрес **без завершающего `/`**) и
   `PUBLIC_DEPLOY_ENABLED=true`. Запустить **Deploy public site** вручную для
   `main`, затем выпуски будут идти после успешного CI автоматически.

Прямое подключение Neon держит минимум соединений для небольшого стенда.
Фоновый worker работает в том же контейнере: если любой из двух процессов
завершится, supervisor завершит сервис целиком, чтобы Render перезапустил его.
После сна worker разбирает накопленные операции; доступность мест дополнительно
проверяется самим API.

## CI/CD и достоверная DORA

CI тестирует API, интерфейс, Chromium, материалы курса, секреты/зависимости и
собирает три образа: API, frontend и публичный контейнер. Сам CI не считается
развёртыванием. [deploy-public.yml](../../.github/workflows/deploy-public.yml)
выпускает только commit `main`, для которого успешны все шесть jobs CI.
Прогоны PR и fork не получают секрет deploy hook.

[Скрипт выпуска](../../scripts/course/deploy_public.py) передаёт Render точный
SHA через параметр `ref`, ждёт до 15 минут и проверяет:

- `/api/v1/release` возвращает **тот же SHA**, а не старую доступную версию;
- health и каталог отвечают корректно, каталог не пуст;
- прямой переход на страницу React возвращает построенный интерфейс.

Принятая Render попытка получает запись GitHub Deployment в `public-demo`;
success ставится после smoke, failure — при истечении ожидания или ошибке
проверки. Отклонённый hook не считается попыткой. Повторный запуск для уже
работающего исправного SHA пропускается без новой записи. Первый выпуск
Blueprint предшествует настройке hook и требует отдельного подтверждения:
повторный workflow не создаёт задним числом deployment для него.
Протокол без секретов и свежая история API доступны в артефакте
`public-deployment` на 7 дней. Отключённый workflow не означает успешный деплой.

Цели следующего цикла: **≥5 полезных выпусков/неделю**, медиана commit→сайт
**≤15 минут**, CFR **≤15%** на следующих ≥10 обычных попытках,
восстановление **≤5 минут**. Они не подставляются в измерения. Выпуски делаются
после готовых изменений; пустые перевыпуски ради счётчика не нужны.
Дата пересчёта — **20.11.2026**. Разные среды и отдельная проверка отказов
считаются раздельно; отсутствие журнала инцидентов сохраняет CFR неизвестным.

## Ограничения Free

[Render Free](https://render.com/docs/free) засыпает после 15 минут без запросов,
первое открытие затем может занять около минуты. Worker также спит;
локальный диск не сохраняется между пересозданиями. Используется только БД Neon,
никаких важных данных на файловой системе контейнера. Лимиты бесплатного
рабочего пространства и сервиса проверяются до создания; переход на платный
тариф не включается.

[Neon Free](https://neon.com/pricing) не ограничен пробным сроком и не требует
карты; на дату 06.11.2026 включены 100 CU-часов/месяц и 1 ГБ на проект.
Бесплатный PostgreSQL самого Render не выбран из-за истечения через 30 дней.

У Render Free закрыты исходящие SMTP-порты 25/465/587. В начальном Blueprint
почта выключена явно: восстановление по email вернёт понятную временную
недоступность, пока не настроен разрешённый внешний почтовый транспорт.
Подключение такой почты и фактическая доставка не считаются проверенными.
Публичный учебный сайт использует тестовую оплату, без банковских списаний;
приватная демонстрационная почта и известные тестовые аккаунты не включены.
