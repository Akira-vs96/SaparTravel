# Восстановление пароля и доставка писем

Ссылка «Забыли пароль?» открывает `/forgot-password`. Пользователь вводит
адрес регистрации, получает одинаковый ответ для известных и неизвестных
аккаунтов, затем открывает одноразовую ссылку `/reset-password?token=…`.
Новый пароль вводится дважды. После успешной смены старые сессии отозваны;
новый запрос делает прежние ссылки недействительными.

## Внешняя доставка

В приватной серверной конфигурации заполнить параметры своего почтового
сервиса. Их действительные значения берутся у владельца SMTP-сервиса;
доступы в Git не записываются.

```dotenv
MAIL_DELIVERY_MODE=smtp
SMTP_HOST=mail.example.com
SMTP_PORT=587
SMTP_FROM_EMAIL=noreply@example.com
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_SECURITY=starttls
PUBLIC_WEB_URL=https://your-site.example
```

Если сервер требует авторизацию, username/password задаются вместе.
Для порта прямого TLS обычно выбирается `SMTP_SECURITY=ssl`; параметры
должны совпадать с настройками конкретного сервиса. Сертификат и имя сервера
проверяются стандартным TLS-контекстом. Незашифрованный режим разрешён
только для loopback-приёмника вне production.

API и worker получают одинаковую конфигурацию. После её изменения
пересоздать оба сервиса:

```bash
docker compose up -d --build api worker
```

`PUBLIC_WEB_URL` должен вести на адрес, доступный получателю письма.
`localhost` в письме с публичного сервера будет ссылаться на компьютер
получателя, а не на приложение. Настройка SMTP не заменяет настройку
действительного домена отправителя у почтового сервиса.

## Очередь и повторная попытка

Новая таблица `outbound_emails` добавляется миграцией 0006 без изменения
существующих пользователей, бронирований и локальных писем. Запись письма
и токена происходит одной транзакцией. До её commit отправки нет.

Worker берёт отдельную строку с блокировкой PostgreSQL `SKIP LOCKED`.
Временная ошибка сохраняет письмо и увеличивает задержку 60/120/240/480 с;
число попыток ограничено `MAIL_MAX_ATTEMPTS`. Просроченные или заменённые
ссылки не отправляются. После принятия SMTP-сервером состояние становится
`sent`, время фиксируется, текст с токеном очищается. SMTP имеет границу
подтверждения на сервере доставки: это не подтверждение прочтения письма,
а редкий разрыв соединения до подтверждения может потребовать повтора.

Администратор открывает **Управление → Почта**: режим, отправитель,
число писем в очереди/отправленных/неуспешных/отменённых и последние записи.
Неуспешное письмо с ещё действующей ссылкой можно повторно поставить в очередь.
Пароль SMTP и содержимое писем SMTP этот экран не раскрывает.
У поставщика и туриста нет доступа к этому разделу/API.

В журнал ошибок попадает класс ошибки, а не SMTP-ответ с возможными
персональными данными или доступами. Наличие записи `pending` без попыток
обычно означает, что worker не запущен; `failed` требует проверки конфигурации
или доступности сервиса перед повтором.

## Локальный режим и отсутствие сервиса

При `MAIL_DELIVERY_MODE=auto` SMTP используется, если заданы host/from.
Иначе local выбирается только в тестовом окружении либо в частном
непроизводственном окружении с `DEMO_MAILBOX_ENABLED=true`. В остальных
случаях восстановление недоступно и API возвращает 503 одинаково для
существующего и неизвестного адреса.

В local письма доступны только администратору через отдельный частный ящик
или серверную команду. Интерфейс прямо сообщает, что внешней доставки нет.
Local нельзя включить в production. Получатель публичной формы никогда
не получает токен в ответе API.

## Проверка реализации

[Серверные проверки](../../backend/tests/test_mail_delivery.py) используют
настоящий SMTP-сеанс с отдельным loopback-приёмником: сообщение, UTF-8,
сброс пароля, отказ/повтор, срок ссылки, rollback и конкурентные worker.
Они не отправляют письма посторонним и не удостоверяют конфигурацию
непредоставленного внешнего почтового сервиса.
[Браузерный сценарий](../../tests/browser_engagement.py) проверяет реальную
кнопку входа в восстановление, подтверждение пароля, административный ящик
и смену пароля в профиле.
