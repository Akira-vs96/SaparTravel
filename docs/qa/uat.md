# Передача и решение UAT

Основание: [SOW, раздел 2.6](../sow-sla-slo-sli.md#26-критерии-и-порядок-приёмки).
Технические результаты фиксируются в [журнале проверок](../verification-results.md).
Автоматические проверки и этот лист не оформляют приёмку от имени заказчика.

| Результат | Демонстрация принимающему | Подтверждение |
|---|---|---|
| D1 | Версия требований, границы, ADR, критерии | [SOW](../sow-sla-slo-sli.md), [план](../implementation-plan.md) |
| D2 | Поиск, карточка, вход, чужие ресурсы/роли | API-тесты и browser_management/browser_smoke |
| D3 | Участники/услуги, KZT, оплата, отмена/возврат, ru/kk/en, конкуренция | commerce/concurrency/engagement и браузерные пути |
| D4 | Запуск, миграции, нагрузка, восстановление, документация | [JSON-доказательства](../ops/evidence/2026-10-30/), [runbook](../ops/runbook.md) |

## Сценарий демонстрации

1. Запустить отдельную демонстрационную среду по README; получить частные доступы.
2. Турист: поиск → тур → участники/услуга → расчёт KZT → тестовая оплата →
   подтверждение/ICS → отмена → фактический возврат и уведомление.
3. Проверить отказ карты, незавершённый 3DS, истёкший резерв и недоступность чужой брони.
4. Vendor: собственный тур/переводы/выезд, публикация, отказ снизить вместимость
   ниже занятой, отсутствие доступа к чужим данным.
5. Admin: новая категория → промокод с этой категорией; отмена менеджером
   с совпадающей предварительной и фактической суммой возврата.
6. Поддержка: P1/P2/P3 → подтверждение приоритета → содержательная первая реакция;
   сверить срок/рабочие минуты и журнал без персональных данных.
7. Повторить важные экраны на ru/kk/en и 360/768/1440; проверить Tab/Escape.
8. Открыть полные отчёты нагрузки и восстановления, ограничения локального стенда,
   команды запуска, отката и включения эксплуатационных timers.

## Решение заказчика

- Версия релиза / commit: заполняется при передаче.
- Представитель заказчика и дата демонстрации: заполняются принимающим.
- По каждому D1–D4: принято / замечания со ссылкой на критерий.
- Неблокирующие замечания: дефект, ответственный, согласованный срок.
- Решение о приёмке: ожидает явного решения заказчика; отсутствие ответа не означает приёмку.

## До активации эксплуатационного SLA

Владелец инфраструктуры подтверждает публичный URL/HTTPS, три независимых
внешних узла с минутными журналами, включённые timers, защищённое хранилище
копий вне сервера приложения и работающий канал регистрации/эскалации инцидентов.
Стороны утверждают календарь поддержки, ответственных, систему заявок,
эксплуатационный контур/ресурсы, плату F, права и дату начала SLA.
Эти данные не выдумываются разработчиком из локального теста.
