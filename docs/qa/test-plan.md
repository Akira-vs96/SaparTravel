# План тестирования и UAT

## 1. Цель тестирования

Обеспечить качество релизов и подтверждение пользовательской ценности на каждом этапе.

## 2. Уровни тестирования

### Unit
- проверки бизнес-логики;
- проверки форматов и правил валидации;
- тесты для интеграционных адаптеров.

### Integration
- проверка взаимодействия API и баз данных;
- проверка сценариев записи/отправки заявок;
- проверка обмена данными с внешними сервисами.

### E2E
- сценарии поиска и фильтрации;
- оформление заявки и статуса;
- регистрация и логин пользователя.

## 3. UAT

### Входные сценарии
- поиск услуги по ключевому слову;
- фильтрация по местоположению и стоимости;
- просмотр карточки партнёра;
- подача заявки;
- получение статуса и обратной связи.

### Критерии приёмки
- сценарий выполняется без ошибок;
- пользователь понимает следующую стадию действий;
- главные риски по UX и данным закрыты.

## 4. Postmortem

После каждого заметного инцидента или релиза:
- фиксировать корневую причину;
- описывать что сработало и что не сработало;
- документировать меры по улучшению процесса;
- обновлять действия в RAID и runbook.

## 5. Ключевые метрики качества

- количество найденных дефектов на релиз;
- процент успешных сценариев E2E;
- время на устранение инцидента;
- количество повторных обращений по одному и тому же вопросу.
